:line

collide command :h3

[Syntax:]

collide style args keyword value ... :pre

style = {none} or {vss} or {table} :ulb,l
args = arguments for that style :l
  {none} args = none
  {vss} args = mix-ID file
    mix-ID = ID of mixture to use for group definitions
    file = filename that lists species with their VSS model parameters
  {vss/kk} args = mix-ID file
    mix-ID = ID of mixture to use for group definitions
    file = filename that lists species with their VSS model parameters
  {table} args = mix-ID file interp N
    mix-ID = ID of mixture to use for group definitions
    file = filename that lists species with their VSS model parameters
           and their tabulated cross sections
    interp = {lookup} or {linear} or {spline} = interpolation style
    N = # of interpolation points per factor of 2 in collision energy
  {table/kk} args = mix-ID file interp N
    same arguments as the {table} style :pre
zero or more keyword/value pairs may be appended :l
keyword = {relax} :l
  {relax} value = {constant} or {variable} :pre
:ule

[Examples:]

collide none
collide vss all ../data/air.vss
collide vss species all.vss relax variable
collide table air ar.tab.vss linear 64
collide table species all.tab.vss spline 32 relax variable :pre

[Description:]

Define what style of particle-particle collisions will be performed by
SPARTA each timestep.  If collisions are performed, particles are
sorted into grid cells every timestep and the appropriate collision
model is invoked on a per-grid-cell basis.  Collisions alter the
velocity of participating particles as well as their rotational and
vibrational energies.  The rotational and vibrational properties of
each species are set in the file read by the "species"_species.html
command.

The collision style determines how many pairs of particles are
considered for collisions, the criteria for which collisions actually
occurs, and the outcome of individual collision, which alters the
velocities of the two particles.  If chemistry is enabled, via the
"react"_react.html command, particles involved in collisions may also
change species, or a particle may be deleted, or a new particle
created.  The "collide_modify"_collide_modify.html command can also be
used to alter aspects of how collisions are performed.  For example,
it can be used to turn on/off the tracking of vibrational energy and
its exchange in collisions.

A {mix-ID} argument is specified for each collision style.  It must
contain all the species defined for use by the simulation, via the
"species"_species.html command.  The group definitions in the mixture
assign one or more particle species to each group.  These groupings
are used to determine how pairs of particles are chosen to collide
with each other, in the following manner.

Consider a cell with N particles and a mixture with M groups.  Based
on its species, each particle is assigned to one of the M groups.
Each unique pair of groups is considered, including each group paired
with itself.  For each pair of groups a value {Nattempt} 
(see equation 11.3 in "(Bird94)"_#Bird94) is calculated  
which is the number of collisions to attempt.  This is a function of
N1 and N2 (the number of particles in each group), the grid cell
volume, and other parameters of the collision style.

For each collision attempt, a random pair of particles is selected,
with one particle from each group.  Whether the collision occurs or
not is a function of the relative velocities of the two particles,
their respective species, and other parameters of the collision
style; see equation 11.4 in "(Bird94)"_#Bird94.

NOTE: If you are using the ambipolar approximation with charged
species, as described in "Section 6.11"_Section_howto.html#howto_11,
and you have used the "collide_modify ambipolar
yes"_collide_modify.html command to enable ambipolar collisions (not
required), and you are using a mixture ID with multiple groups, then
the ambipolar electron species must be in a group by itself.

:line

The {none} style means that no particle-particle collisions will be
performed, i.e. the simulation models free-molecular flow.

:line 

The {vss} style implements the Variable Soft Sphere (VSS) model for
collisions.  As discussed below, with appropriate parameter choices,
it can also compute the Variable Hard Sphere (VHS) model and the Hard
Sphere (HS) model.  See chapters 2.6 and 2.7 in "(Bird94)"_#Bird94 for
details.

In DSMC, the variable-soft-sphere (VSS) interaction of "Koura and
Matsumoto"_#Koura92 and the variable-hard-sphere (VHS) interaction of
"Bird"_#Bird94 are used to approximate molecular interactions.  Both
models yield transport properties proportional to a power (omega) of
the gas temperature.  This temperature dependence of the transport
properties is similar to the Inverse Power Law model (IPL) for which
Chapman-Enskog theory provides closed form solutions for the transport
properties.

Both VSS and VHS interactions define parameters {diam} = molecular
diameter, which is a function of the molecular speed, and {alpha} =
angular-scattering parameter, which relates the scattering angle to
the impact parameter.  Setting {alpha} = 1 produces isotropic (hard
sphere) interactions, which converts the VSS model into a VHS model.

The {file} argument is for a collision data file which contains
definitions of VSS model parameters for some number of species.
Example files are included in the data directory of the SPARTA
distribution, with a "*.css" suffix.  The file can contain species not
used by this simulation; they will simply be ignored.  All species
currently defined by the simulation must be present in the file.

The format of the file depends of the setting of the optional {relax}
keyword, as explained below.  Comments or blank lines are allowed in
the file.  Comment lines start with a "#" character.  All other lines
must have the following format with parameters separated by
whitespace.

If the {relax} keyword is specified as {constant}, which is the
default, then each line has 4 parameters following the species ID:

species-ID diam omega tref alpha :pre

The species-ID is a string that will be matched to one of the species
defined by the simulation, via the "species"_species.html command.
The meaning of additional properties is as follows:

diam = VHS or VSS diameter of particle (distance units)
omega = temperature-dependence of viscosity (unitless)
tref = reference temperature (temperature units)
alpha = angular scattering parameter (unitless) :ul

The methodology for deriving VSS/VHS parameters from these properties
is explained in Chapter 3 of "(Bird94)"_#Bird94.  Parameter values for
the most common gases are given in Appendix A of the same book.  These
values are based on the first-order approximation of the
Chapman-Enskog theory.  Infinite-order parameters are described in
"(Gallis04)"_#Gallis04.

In the {constant} case rotational and vibrational relaxation during a
collision is treated in the same constant manner for every collision,
using the rotational and vibrational relaxation numbers from the
species data file, as read by the "species"_species.html command.

If the {relax} keyword is specified as {variable}, then each line has
8 parameters following the species ID:

species-ID diam omega tref alpha Zrotinf T* C1 C2 :pre

The first 4 parameters are the same as above.  Parameters 5 and 6
affect rotational relaxation; parameters 7 and 8 affect vibrational
relaxation.  In this case the rotational and vibrational relaxation
during a collision is treated as a variable and is computed for each
collision.  This calculation is only performed for polyatomic species,
using equations A5 and A6 on pages 413 and 414 in "(Bird94)"_#Bird94,
with the modification that the collision temperature is calculated
using energy in the internal mode as well as the translational mode.
Zrotinf and T* are parameters in the numerator and denominator of eq
A5.  C1 and C2 are in eq A6.  The units of these parameters is as
follows:

Zrotinf (unitless)
T* (temperature units)
C1 (temperature units)
C2 (temperature^(1/3) units) :ul

Note that a collision data file with the 4 extra relaxation parameters
(per species) can be used when the {relax} keyword is specified as
{constant}.  In that case, the extra parameters are simply ignored.

For interspecies collisions, the collision parameters default to
the average of the parameters for each involved species.  To override
this default, lines specific to each interspecies pair can be added
anywhere in the collision data file.  The format for these lines is as
described above, with the addition of a second species name.  For
example, with the {relax} keyword specified, an interspecies
collision line would contain the following information for collisions
between species-ID and species-ID1:

species-ID species-ID1 diam omega tref alpha Zrotinf T* C1 C2 :pre

In an interspecies line, a specific parameter can be returned to the
default behavior (an average) by making it negative.  For example, to
override only {omega} for the above case, the line could appear as
follows:

species-ID species-ID1 -1 omega -1 -1 -1 -1 -1 -1 :pre

:line

The {table} style replaces the analytic VHS/VSS total cross section with
an arbitrary cross section read from a file and interpolated at run time.
It is the collision analog of the "pair_style table" command in LAMMPS.
Use it when the interaction of interest is not well described by the
single power law the VSS model assumes, e.g. for ab initio elastic cross
sections, momentum-transfer cross sections derived from collision
integrals, or resonant charge-exchange data.

Everything other than the total cross section is inherited from the {vss}
style: the number of attempted collisions, the post-collision scattering
angle, rotational and vibrational energy exchange, chemistry, and the
ambipolar approximation all behave exactly as described above.  Only the
probability that a selected pair actually collides is changed.

One consequence of that inheritance needs care, and the {table} style
handles it for you.  For a colliding pair in equilibrium, the joint
density of the relative translational energy Et and one internal mode of
zeta degrees of freedom is

f(Et,Ei) ~ sigma(Et) Et Ei^(zeta/2-1) exp(-(Et+Ei)/kT) :pre

the Et factor being sigma(Et)*g times the Et^1/2 density of states.  A
Larsen-Borgnakke exchange holds Ec = Et + Ei fixed, so it leaves that
density stationary exactly when the post-collision Et is drawn from

P(Et|Ec) ~ sigma(Et) Et (Ec-Et)^(zeta/2-1) :pre

For the VHS law sigma ~ Et^(1/2-omega) this is the Et^(3/2-omega) weight
the {vss} style samples, which is where its exponent comes from.  A
tabulated cross section is not that power law, so sampling the VSS weight
would break detailed balance and let a gas started in equilibrium drift.
The {table} style therefore makes the same draw and then accepts it with
probability proportional to sigma_table(Et)/sigma_VHS(Et), normalized by
the largest that ratio attains over the energies reachable at this Ec.
That is an exact sampler for P(Et|Ec) for any cross section whatsoever,
not an approximation, and it reduces to the {vss} sampler identically when
the table follows the VHS law.

The correction is applied only to pairs which have both a cross section
table and an internal mode, and it costs one acceptance test per draw.
SPARTA prints the worst-case acceptance ratio at setup.  A table close to
the VHS power law of its pair accepts almost every draw; one that departs
far from it accepts less often and the energy exchange for that pair is
correspondingly slower.  Choosing {diam} and {omega} for the pair to
follow the table reduces the cost, and now affects only the cost, never
the answer.

The translational part of the collision conserves momentum and energy
exactly whatever the cross section, and always did.

The {file} argument is a VSS parameter file, in exactly the format
described above for the {vss} style, with additional "table" directive
lines which may appear anywhere in the file:

species-ID species-ID1 table filename keyword :pre

This assigns the cross section stored in section {keyword} of the file
{filename} to collisions between species-ID and species-ID1.  A pair with
no table directive uses the analytic VSS cross section, so a tabulated
cross section can be introduced for one pair of an existing multi-species
model without changing any of the others.

Two further directives tabulate the {deflection angle} rather than the
cross section:

species-ID species-ID1 alpha filename keyword
species-ID species-ID1 scatter filename keyword :pre

An {alpha} directive supplies an energy-dependent VSS alpha, replacing the
constant alpha from the VSS parameters for that pair.  A {scatter}
directive supplies the full angular distribution, replacing the VSS
scattering law entirely.  Both require the pair to also have a {table}
directive, since they change only how a collision deflects, not whether
it occurs.

Why this matters: a total cross section with a constant alpha reproduces
one transport cross section exactly at all temperatures.  The VSS model
gives

Q1 / sigma_T = 2/(1+alpha)
Q2 / Q1 = 2 alpha/(2+alpha) :pre

where Q1 and Q2 are the diffusion and viscosity cross sections.  With both
sigma_T(E) and alpha(E) tabulated, both are reproduced at every collision
energy, which no single (diam, omega, alpha) triple can do.  A {scatter}
table goes further and reproduces the whole angular distribution, which
matters when the flow is far from equilibrium.

VSS parameters are still required for every species, even when every pair
is tabulated.  They are used for pairs without a table, by the
"react"_react.html styles and the "compute lambda/grid"_compute_lambda_grid.html
command, and by the {vss} extrapolation mode described below.

:line

A cross section file contains one or more sections.  Each section begins
with a keyword line naming the section, followed by a parameter line,
followed by N lines of data.  Blank lines and comment lines beginning
with "#" may appear anywhere.  For example:

# Ar-Ar elastic total cross section :pre

AR_AR_ELASTIC
N 200 X energy XUNITS eV YUNITS A^2 EXTRAP powerlaw constant :pre

1     1.0000e-04   1.352e+02
2     1.2000e-04   1.301e+02
...
200   1.0000e+03   3.110e+00 :pre

Each data line has 3 columns: an index, the independent variable, and the
total cross section.  The index is ignored.  The independent variable must
be positive and must increase monotonically.  The cross section must be
non-negative.

The parameter line keywords may appear in any order.  Only {N} is
required:

{N} n = number of data lines in this section
{X} {energy} or {speed} = independent variable, default {energy}
  {energy} = relative translational energy 1/2*m_r*g^2
  {speed} = relative speed g
{XUNITS} {eV} or {J} or {K} or {m/s} = units of the independent variable
  default is {eV} for {energy} and {m/s} for {speed}
  {K} means the energy is given as E/k_B
{YUNITS} {m^2} or {cm^2} or {A^2} = cross section units, default {m^2}
{EXTRAP} lo hi = behavior below and above the tabulated range,
  each of {constant} or {powerlaw} or {vss} or {error},
  default {constant} {constant} :ul

The {EXTRAP} modes are:

{constant} = hold the cross section fixed at its value at that end
{powerlaw} = extend the power law fit to the two end points, which is
  the right choice for a cross section which continues to rise or fall
  as a power of the energy, such as a polarization-limited tail
{vss} = fall back to the analytic VSS cross section for that species pair
{error} = abort if a collision is attempted outside the tabulated range :ul

Note that the extrapolated cross section is used for any collision energy
outside the table, so a table which does not span the energies sampled by
the simulation will silently use the extrapolation unless {error} is
selected.  When the tables are read, SPARTA prints the energy range of
each table so this can be checked against the temperatures in the run.

A {scatter} section is two dimensional.  Its parameter line adds an {M}
keyword giving the number of angles, and each data row holds M values of
cos(chi) at equally spaced cumulative probabilities (j+1/2)/M, i.e. the
inverse cumulative differential cross section at that energy:

AR_AR_SCATTER
N 120 M 64 X energy XUNITS eV EXTRAP constant constant :pre

1  1.0000e-04  -0.9987 -0.9954 ... 0.9999
... :pre

An {alpha} section is an ordinary one-column section whose values are the
VSS alpha; {YUNITS} does not apply to it.

Electron-neutral collisions are a natural use of this style, since
electron-neutral cross sections are measured rather than modelled and often
have structure, such as a Ramsauer-Townsend minimum, that no VHS power law
can represent at all.  They work with the ambipolar approximation: an
ambipolar electron carries its own velocity into the collision, so a
tabulated sigma(E) is evaluated at the true electron energy even though the
electron is advected with its parent ion.

When electrons are present, put the electron species in a collision group of
its own.  The "fix ambipolar"_fix_ambipolar.html command requires this
whenever the mixture has more than one group, as noted above, and it also
matters for cost: grouping the fast electrons together with the heavy
species makes the NTC attempt count much larger, since the attempt rate for
the whole group is set by the fastest pairs in it.  In the
examples/table/in.table.electron problem, moving the electron into its own
group cuts the attempt count by a factor of five and the run time by nearly
three.

Note also that a tabulated electron-neutral cross section is indexed by the
relative translational energy, whose reduced mass is essentially the
electron mass, so the energy axis of an electron-neutral table is unrelated
to that of a neutral-neutral table for the same species.
{tabulate_cross_section.py} takes the masses from the species file and
handles this.

Each table is binned logarithmically with N bins per factor of 2 in
energy, so a table spanning a factor R in energy holds N*log2(R) bins, and
each bin holds 1, 2 or 5 coefficients for the {lookup}, {linear} and
{spline} styles.  A table covering 1e-3 to 1e3 eV at N = 256 with {linear}
is about 5000 bins, or 80 KB, and every MPI rank holds a copy of every
table.  That is negligible for a handful of pairs, but a model which
tabulates all pairs of a many-species mixture at large N with {spline}
should be sized before it is run.  The per-table bin count is printed at
setup.

The tools directory contains {tabulate_cross_section.py}, which writes
files in this format.  It can convert a two-column list of energy and
cross section values, emit the analytic VHS/VSS cross section for a
species pair (useful for verifying that a tabulated run reproduces the
equivalent {vss} run), compute cross sections directly from an
intermolecular potential, or convert a file exported from the
"LXCat"_https://www.lxcat.net project, which is the standard source of
electron-neutral cross sections.  The {lxcat} mode lists the processes in a
downloaded file, converts the one selected, and copies the database name,
the retrieval date, that database's own "HOW TO REFERENCE" text, and the
comments attached to the data group and to the individual cross section
into the generated table, so the attribution LXCat asks for travels with
the data.  Note that LXCat's terms of use forbid redistributing the data,
so a converted table should not be committed to a public repository.

Note also what LXCat means by its process keywords.  {ELASTIC} denotes the
elastic momentum-transfer cross section Q1, not the integral elastic cross
section, and {EFFECTIVE} denotes the total momentum transfer, i.e. the sum
of the elastic momentum transfer and the total inelastic cross sections.
Neither is a total collision cross section.  Using either as a {table}
cross section is nevertheless the right thing to do provided the pair
scatters isotropically, alpha = 1, because for isotropic scattering Q1 and
sigma_T coincide, so the simulation reproduces the tabulated
momentum-transfer rate exactly.  Do not combine an {EFFECTIVE} set with
separate inelastic cross sections for the same pair, or the inelastic
channels are counted twice.

The {potential} mode integrates the classical deflection angle

chi(b,E) = pi - 2 b int_rm^inf dr / (r^2 sqrt(1 - b^2/r^2 - V(r)/E)) :pre

for a Lennard-Jones 12-6 potential or a tabulated V(r), and forms the
transport cross sections Q1 and Q2 from it.  It offers three conventions
for the total cross section, which is formally infinite for a potential of
infinite range:

{viscosity} = sigma_T = (3/2) Q2, which with isotropic scattering
  (alpha = 1) reproduces the viscosity at every temperature
{transport} = sigma_T(E) and alpha(E) chosen to reproduce both Q1 and Q2
{cutoff} = sigma_T = pi b_max^2 with the true angular distribution,
  emitted as a scatter table :ul

In {cutoff} mode the choice of b_max sets how many collisions the
simulation performs, and a b_max large enough to capture the potential's
tail makes sigma_T very large, so most collisions barely deflect.  The
{--chimin} option instead fixes b_max at each energy from the smallest
deflection angle worth simulating.  For Lennard-Jones argon at 0.03 eV,
cutting at 1 degree gives a sigma_T ten times smaller than a fixed b_max of
8 sigma while changing the viscosity cross section by 0.03%; cutting at 5
degrees gives eighteen times smaller for 0.5%.  The
"collide_modify scheme mcf"_collide_modify.html majorant scheme can also be
used with any tabulated cross section.

Its numerics can be checked against the standard tabulated Lennard-Jones
collision integrals with the {--selftest} option.

:line

The {interp} and {N} arguments control how the tabulated data is
interpolated, in the same spirit as the LAMMPS "pair_style table"
command.  When the file is read, the input data is splined, in log-log
whenever every cross section is positive, and resampled into an internal
table of bins.  At run time the bin holding a collision is found directly
from the exponent and leading mantissa bits of the relative velocity
squared, so a lookup requires no division, square root, logarithm, or
power, and is somewhat cheaper than evaluating the analytic VSS cross
section.

Because the bins are found from the floating-point exponent, they are
spaced logarithmically: {N} is the number of bins per factor of 2 in
collision energy, and is rounded up to a power of 2.  Every bin therefore
has the same relative width, and a table may span many decades of energy
without losing resolution at the low end.  {N} = 64 gives bins about 1%
wide in energy, which is accurate to roughly 1 part in 10^5 with the
{linear} style for a smooth cross section.

The interpolation styles are:

{lookup} = use the value at the center of the bin, no interpolation
{linear} = linear interpolation within the bin
{spline} = cubic interpolation within the bin, matching the value and
  slope of the input data at both bin edges :ul

After each table is built, SPARTA compares it against the input data, at
every input point and at the center of every bin, and prints the largest
relative deviation.  A warning is issued if it exceeds 1%, which
indicates that {N} is too small to resolve the structure in the data.

:line

Styles with a {kk} suffix are functionally the same as the
corresponding style without the suffix.  They have been optimized to
run faster, depending on your available hardware, as discussed in the
"Accelerating SPARTA"_Section_accelerate.html section of the manual.
The accelerated styles take the same arguments and should produce the
same results, except for different random number, round-off and
precision issues.

These accelerated styles are part of the KOKKOS package. They are only
enabled if SPARTA was built with that package.  See the "Making
SPARTA"_Section_start.html#start_3 section for more info.

You can specify the accelerated styles explicitly in your input script
by including their suffix, or you can use the "-suffix command-line
switch"_Section_start.html#start_7 when you invoke SPARTA, or you can
use the "suffix"_suffix.html command in your input script.

See the "Accelerating SPARTA"_Section_accelerate.html section of the
manual for more instructions on how to use the accelerated styles
effectively.

:line

[Restrictions:]

The {table} style has a {kk} suffixed variant which implements everything
the plain style does: the total cross section, the energy-dependent alpha,
the scatter table, the Larsen-Borgnakke detailed balance correction, and
the {error} extrapolation mode, which is recorded on the device and raised
by the host after the collision kernel since device code cannot raise an
error itself.  "compute lambda/grid"_compute_lambda_grid.html also takes
the tabulated cross section on the device, so the mean free path and
collision time which drive "fix adapt"_fix_adapt.html and "fix
dt/reset"_fix_dt_reset.html are the tabulated ones there too.  It is
verified against the non-KOKKOS build with SPARTA_KOKKOS_EXACT, which
makes the two agree bit for bit.

The "react tce"_react.html model derives its reaction probability as the
ratio of the reaction cross section to the VHS total cross section.  When
a tabulated total cross section is used to select collision pairs, SPARTA
rescales that probability by the ratio of the VHS to the tabulated cross
section, so that the reaction rate coefficients in the reaction file are
still reproduced.  This means the reaction rates depend on the VSS
parameters in the collision file, not on the tabulated cross sections.

[Related commands:]

"collide_modify"_collide_modify.html, "mixture"_mixture.html,
"react"_react.html

[Default:]

Style = none is the default (no collisions).  If the vss or table style
is specified, then relax = constant is the default.  For the table style,
a cross section file section with no {EXTRAP} keyword uses {constant}
extrapolation at both ends.
