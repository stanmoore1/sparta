Every applied bug fix was run against the unfixed code and the fixed code, with a positive control to show the bug is real (the fix is necessary), variant runs across call paths, dimensions and rank counts (the fix is complete), and a negative control on valid input (nothing else changed). Gaps found this way were fixed and run through the same A/B again.

How the A/B runs were done

  • Builds. Base e071055f, round-1 fix 4a13279b, round-2 e14de2c9, round-3 215840e0. Each built three ways: serial (STUBS), OpenMPI, and OpenMPI with AddressSanitizer + UBSan + LeakSanitizer; FFT and PYTHON packages included.
  • Positive control. A minimal input deck that reaches the buggy line. The base build had to misbehave observably: crash, sanitizer report at the buggy function, hang at np 2–4 under a timeout, a value differing from a hand-computed or analytic expectation, or a wrong error message.
  • Completeness. Each trigger variant run on both builds: 2d and 3d, serial and parallel, each keyword or style branch, boundary values, empty ranks. Sibling code with the same pattern was searched for and reported if left unfixed.
  • Negative control. Closely related valid input; base and fix must agree (byte-identical, or statistically equivalent where an intended fix legitimately changes the RNG stream).
  • Harness. Where no input deck reaches the code (latent functions, >231 sizes, single-precision FFT, PNG/VTK/FFmpeg builds, library API), a small C++ driver was built from each tree's own sources or objects and run under sanitizers.
Caveat. Three test agents ran broad pkill patterns at different times and may have killed each other's runs briefly. Every reported verdict is backed by runs recorded in its own log, and no verdict rests on a single killed run.
