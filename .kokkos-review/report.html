KOKKOS fix verification: is each fix necessary and complete?

Every bug fix from the line-by-line review of the KOKKOS package was A/B tested: the pre-fix build (A, commit e071055f) against the fixed build (B), with the CPU styles of the same binary as a reference. A fix counts as necessary when A demonstrably misbehaves on the buggy path, and complete when B is correct on every variant the fix covers and no sibling site keeps the bug.

Method

Builds

A: commit e071055f. B: all review fixes. C: B plus follow-ups. Each as an OpenMP build with MPI stubs, and as a real-MPI build with Kokkos DEBUG_BOUNDS_CHECK so out-of-bounds view accesses abort.

Controls

Positive control: an input on the buggy path where A fails (wrong value vs CPU or analytic, crash, bounds abort, NaN, hang, leak). Negative control: same code path without the trigger; A and B must agree.

Coverage

Kernel paths (atomic, duplicated, sorted), 1 and 4 threads, 1 to 4 MPI ranks, 2D and 3D, each surface collision model. Standalone unit drivers for unreachable or library-only paths.

Regression

All 141 example inputs with Kokkos on: thermo output identical between A and B except ambi, which now runs further; identical between B and the final build with all follow-up fixes, and again after round 2 (141/141).

GPU memory

Split-memory detector builds (separate host allocation, software DualView state machine; watch, stale, audit and AddressSanitizer poison modes) of the pre-fix and fixed code. All 134 examples at 1 rank and 21 at 4 ranks match stock stats on the fixed code.

Limits

No GPU on the test machine. The split-memory tool reproduces most host/device coherence bugs, but not a kernel dereferencing a host pointer or host code touching device-only memory. No SPARTA_KOKKOS_EXACT build was made.
