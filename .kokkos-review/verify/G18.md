### F-G18-1
VERDICT: CONFIRMED
reason: ParticleKokkos::k_species2group is only (re)built in ParticleKokkos::wrap_kokkos() (particle_kokkos.cpp:965-970), which is called only from UpdateKokkos::setup() under `if (sparta->kokkos->prewrap)` (update_kokkos.cpp:350-366), and prewrap is set to 0 right after the first setup. No other writer (grep). Mixture::init recomputes mixture[i]->species2group every run, and the `mixture` command (new mixture, or `group` keyword changing membership) is legal between runs, so on run 2 d_s2g(imix,isp) is stale (wrong group filtering) or, for a mixture/species created after run 1, out of the extent nmixture_old x nspecies_old -> device OOB read. CPU reads particle->mixture[imix]->species2group live. compute_reduce_kokkos.cpp:671-681 already documents and works around this for itself. Affects every consumer of k_species2group (gas/surf collision/reaction tally, gas collision/reaction grid, compute surf/isurf/boundary kk...).
fix: root fix in ParticleKokkos/UpdateKokkos: move the species2group block of ParticleKokkos::wrap_kokkos() (particle_kokkos.cpp:965-970) into a new `void ParticleKokkos::update_species2group()` and call it unconditionally in UpdateKokkos::setup() (update_kokkos.cpp, before/after the prewrap block; sparta->init() -> Mixture::init has already run by then), so the dual view is rebuilt with the current nmixture x nspecies every run. Consumers already re-fetch d_s2g in pre_*_tally()/init each run, so no change is needed there.
