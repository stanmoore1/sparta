### F-G11-2
VERDICT: CONFIRMED
cpu-also: yes
reason: The per-surf row is a plain running sum (fix_emit_surf.cpp:374-379) of the fractions after FixEmitSurf::init's unset-fill (fix_emit_surf.cpp:302-326); unlike Mixture::init_fraction (mixture.cpp:305) the last entry is never forced to 1.0, and the selection loop (kokkos :739, cpu :858) has no isp<nspecies bound. The finding's specific example (0.1/0.2/-1) is wrong — that sums to exactly 1.0. When all fractions are set, init requires sum==1.0 computed in the same sequential order, so the last cumulative is exactly 1.0 (safe). But with >=2 unset entries roundoff leaves it below 1: e.g. 0.3/-1/-1 -> last = 0.9999999999999999 (1-2^-53); 8 species 0.07 + seven -1 -> 0.9999999999999998 (1-2^-52), and lower is possible. Kokkos Random_XorShift64::drand() = urand64()/double(UINT64_MAX) (lib/kokkos/algorithms/src/Kokkos_Random.hpp:975) can return any value up to 1.0, so a draw above the last entry walks isp to nspecies -> reads the next surf's row (or past the view on the last surf) and then d_vscale(i,nspecies)/d_vscale_mix(nspecies)/d_mspecies(nspecies) out of bounds. Probability is ~1e-16 per draw, so rare, but real; same defect in CPU code. Low severity.
fix: src/fix_emit_surf.cpp:379 (after the isp loop, inside the isurf loop) add `cummulative_custom[isurf][nspecies-1] = 1.0;` (mirrors mixture.cpp:305). The Kokkos copy in FixEmitSurfKokkos::grid_changed (kokkos :239-243) picks that up; optionally also bound the loops `while (isp < nspecies-1 && cummulative[isp] < rn) isp++;` at kokkos :739 and fix_emit_surf.cpp:858.
