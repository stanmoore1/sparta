### F-G12-1
VERDICT: CONFIRMED (low-med)
reason: fix_emit_face_kokkos.cpp:813 tests only `if (np)`; CPU src/fix_emit_face.cpp:1109 tests `np && massrho_cell*soundspeed_cell > 0.0` (added in 456f0be9), and fix_emit_face_file_kokkos.cpp:926 already carries the guard. With np>=1 and ke<=0 (roundoff ke<0 -> sqrt(neg)=NaN; or np==1 cannot since np>1 branch, but np>1 identical velocities -> ke==0 -> soundspeed 0) the Kokkos code divides by 0 / propagates NaN into vstream[ndim] and every inserted particle's velocity, where the CPU skips the correction (NaN>0 is false). Note nrho is already inf/NaN in that degenerate case for both CPU and KK (division by soundspeed^2), so practical impact is mostly the NaN-roundoff case; still a parity divergence.
fix: src/KOKKOS/fix_emit_face_kokkos.cpp:813 change `if (np) {` to `if (np && massrho_cell*soundspeed_cell > 0.0) {` (identical to CPU :1109 and fix_emit_face_file_kokkos.cpp:926). Same one-line change in fix_emit_surf_kokkos.cpp:~1178 if it lacks it.
cpu-also: no

### F-G12-2
VERDICT: CONFIRMED (low)
reason: ParticleKokkos::sort_kokkos() sets sorted_kk=1 (particle_kokkos.cpp:269); CPU FixEmitFace::subsonic_sort() (fix_emit_face.cpp:970-1020) builds private lists and never sets particle->sorted. sorted_kk is only reset by move (update_kokkos.cpp:946), setup, compress, reactions; add_particle does not reset it. So when particles are unsorted at step start (no collisions, or reactions occurred -> collide_vss_kokkos.cpp:600-604 clears it), the first subsonic emit/face/kk (or emit/surf/kk, emit/face/file/kk) sorts and leaves sorted_kk=1, then a second subsonic emit fix in the same START_OF_STEP skips sorting and uses a d_plist that omits particles fix 1 just inserted; CPU re-runs subsonic_sort for fix 2 and includes them. Disproof attempt: when collisions are on (no react) CPU also has sorted=1 at step start and has the same staleness, so divergence is limited to the unsorted case — but that case is reachable (subsonic inflow without collide is common).
fix: src/KOKKOS/fix_emit_face_kokkos.cpp:657-658 (and fix_emit_face_file_kokkos.cpp:760-761, fix_emit_surf_kokkos.cpp:979-980): `plist_descending = !particle_kk->sorted_kk; if (!particle_kk->sorted_kk) { particle_kk->sort_kokkos(); particle_kk->sorted_kk = 0; }` — the lists stay valid for this fix's subsonic_grid, but the flag is not left set, matching CPU which leaves particle->sorted untouched.
