### F-G10-1
VERDICT: CONFIRMED
reason: backup() is called via SurfCollide*Kokkos::backup() on KK_SR_H_GLOBAL(m), which (non-FIXED_LISTS) is the host half of the k_sr_global byte buffer filled by sr_buf_blit (memcpy, kokkos_type.h:871-876), and under FIXED_LISTS is a KKCopy obj filled by KKCopy::copy (memcpy). The live surf->sr[n] never allocates d_nsingle_backup/d_tally_single_backup (ctor 28-56, init 84-94 do not), so the image's handles are empty; backup() assigns fresh allocations into the image (refcount 1 owned only by the image). setup_surf_collide_models()->pre_collide() re-blits the original (empty handles) over the image every migration iteration of every step (update_kokkos.cpp ~2760), memcpy does not release, so the allocations are orphaned. Under FIXED_LISTS, KKCopy::~KKCopy restore()s the pristine snapshot, also without release. Reachable whenever do_backup (react_retry_flag with nsr>0, or any per-event surf tally compute; update_kokkos.cpp:738-749). Leak is 2 small device allocations per surf_react global model per backup-iteration; low severity agreed.
fix: allocate the backup views on the live object, e.g. in SurfReactGlobalKokkos::init() (surf_react_global_kokkos.cpp:84-94) after the deep_copies: `d_nsingle_backup = DAT::t_int_scalar("surf_react:nsingle_backup"); d_tally_single_backup = DAT::t_bigint_1d("surf_react:tally_single_backup",nlist);` (or in the kokkos ctor next to k_nsingle/k_tally_single, line 39-45), and drop the lazy allocation in backup() lines 147-155 (keep only the deep_copies; the blitted handles alias the live allocations, so deep_copy into them is valid). Mirrors the random_backup treatment at lines 49-55.

### F-G10-3
VERDICT: CONFIRMED
reason: Grid::notify_changed() (src/grid.cpp:390) calls surf->sr[i]->grid_changed() on the live object during a run (fix balance / fix adapt). For mode SURF + distributed surfs, the CPU base (src/surf_react_adsorb.cpp:1230-1279) destroys/recreates species_delta and mark at the new nall and re-points total_state/species_state/area/weight to the re-spread local arrays. The Kokkos override (surf_react_adsorb_kokkos.cpp:146-150) leaves nstate_ (set only in init_reactions_gs_kokkos:351) and all device per-slot views at the old size. Consequences: tally_update() loops `i < nstate_` over the new host species_delta/mark (497-505, 540-547) -> heap overflow when nall shrank; pre_react() re-points the host pointers each step (403-408) but loops to the old nstate_ (419-425) -> heap over-read; when nall grew, any isurf >= old nstate_ trips the Kokkos::abort guard (h:243), and d_species_delta/d_mark extents are also too small. No error path forbids distributed surfs with Kokkos (no KOKKOS check found). Path is reachable on every grid change that hits a sync step (the CPU errors otherwise). The "pending device deltas renumbered" part is weak (grid_changed must happen on a sync step, after tally_update zeroed the deltas), but the size mismatch alone is a memory-safety bug. cpu-also: no.
fix: in SurfReactAdsorbKokkos::grid_changed() (cpp:146-150), after SurfReactAdsorb::grid_changed(), when `mode == SRA_KK::SURF && distributed` re-run the per-slot allocation block of init_reactions_gs_kokkos() (cpp:351-370): nstate_ = surf->nlocal+surf->nghost; ns = MAX(nstate_,1); reallocate d_total_state, d_area, d_weight, d_species_state(ns,nspecies_surf), k_species_delta/d_species_delta (zeroed, matching CPU memset) and k_mark/d_mark (zeroed), and set state_synced_to_device = 0. Cleanest is to factor lines 349-370 into a helper (e.g. alloc_state_kokkos()) called from both init_reactions_gs_kokkos() and grid_changed(). (If F-G10-5's fix moves backup views to the live object, size them in the same helper.)

### F-G10-4
VERDICT: CONFIRMED
reason: SurfReactAdsorbKokkos::init() (cpp:105-128) runs on every run command and unconditionally calls init_reactions_gs_kokkos(), which re-creates k_species_delta and k_mark and deep_copies them to 0 (cpp:364-370). The device is the only place GS deltas accumulate between sync steps (host species_delta/mark are refreshed from device only on sync steps, cpp:493-507, and that refresh *overwrites* the host array rather than adding). CPU allocates/zeroes surf_species_delta/face_species_delta and mark exactly once (create_per_surf_state/create_per_face_state, src/surf_react_adsorb.cpp:386-397,466-490, called from the ctor; init() is firstflag-guarded at 503-504) and never clears them at run end, so pending deltas carry into the next run's first sync step. With Kokkos, a run ending off a sync step (e.g. `run 105` with nsync 10 then `run 100`) discards the steps-101..105 device deltas (and marks): the particles were already removed/created by the GS reactions but surface coverage is never updated -> wrong surface state. Not a CPU bug. cpu-also: no.
fix: in init_reactions_gs_kokkos() (cpp:359-370) only (re)allocate+zero k_species_delta/d_species_delta and k_mark/d_mark when they are unallocated or their extents differ from (ns,nspecies_surf)/(ns), e.g. `if (k_species_delta.extent(0) != (size_t) ns || k_species_delta.extent(1) != (size_t) nspecies_surf) { k_species_delta = ...; d_species_delta = ...; Kokkos::deep_copy(d_species_delta,0); }` and likewise for k_mark; keep state_synced_to_device = 0 and the state-view allocations. Size changes between runs are already covered by grid_changed (F-G10-3), which zeroes as the CPU does.
