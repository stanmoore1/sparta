# Verify G21

### F-G21-1
VERDICT: CONFIRMED
reason: kokkos.cpp:71 ngpus = atoi(arg) accepts 0/negative; the six getenv blocks (:82-117) compute local_rank % ngpus before the ngpus<=0 check at :142. "-k on g 0" under OpenMPI/Slurm -> SIGFPE. Negative ngpus gives negative device.
fix: kokkos.cpp right after `ngpus = atoi(arg[iarg+1]);` (:71) add `if (ngpus <= 0) error->all(FLERR,"Invalid Kokkos command-line args");`

### F-G21-2
VERDICT: CONFIRMED
reason: kokkos.cpp:123-126 has no bounds check. arg is &argv[kkfirst] with narg=kklast-kkfirst (sparta.cpp:390), so arg[narg] is the next real argv entry (e.g. "-in" -> atoi=0 threads) or argv[argc]==NULL -> atoi(NULL) segfault when "-k on t" ends the command line.
fix: kokkos.cpp:125 insert `if (iarg+2 > narg) error->all(FLERR,"Invalid Kokkos command-line args");` before `nthreads = atoi(arg[iarg+1]);` (same as the d/g branches).

### F-G21-3
VERDICT: REFUTED
reason: buffers are never undersized by a small factor: every use only grows (`if (extent < X_extra) realloc`), and the kernels detect capacity overflow and set d_retry; with retry=no the host then errors "Ran out of space in Kokkos collisions, increase react/extra" (collide_vss_kokkos.cpp:921-925). So react/extra<=1 yields a clean error, not memory corruption. (Input validation `react_extra >= 1.0` would be nice but is not a defect.)
side-observation (not part of this finding, worth a separate check by the collide group): collide_vss_kokkos.cpp:798,1230,1974,2479,3154 apply react_extra only `if (react_retry_flag)`, while doc/package.txt:85-101 says react/extra is the mechanism for retry=no and is ignored for retry=yes, and update_kokkos.cpp:685 uses `!react_retry_flag`. So in the default mode (retry=no) collide ignores react/extra entirely (extra_factor=1.0) and the "increase react/extra" error message is useless advice. Long-standing upstream (since PR #558 merge). Possible fix: `if (!sparta->kokkos->react_retry_flag)` at those lines.
