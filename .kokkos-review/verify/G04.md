### F-G04-1
VERDICT: CONFIRMED
reason: sparta.cpp:563 calls react->init() before each run; ReactBird::init (react_bird.cpp:112-113) zeroes only the host array tally_reactions (= k_tally_reactions.view_host().data()) without modify_host(). ReactBirdKokkos::init (react_bird_kokkos.cpp:98-155) never zeroes d_tally_reactions, and nothing else does (grep: only atomic_inc in react_tce/qk/tce_qk_kokkos.h, backup/restore copy). extract_tally (161-181) does modify_device()+sync_host() (or reduces the device view directly on gpu-aware path), so run-2 Finish tallies (finish.cpp:360) include run-1 counts. ### F-G04-3
VERDICT: REFUTED
reason: For the host backends this path can run on (SPARTA_KOKKOS_GPU errors out), UniqueToken<..., Global> is not a slot allocator: lib/kokkos/core/src/OpenMP/Kokkos_OpenMP_UniqueToken.hpp:84-115 acquire() returns omp_get_thread_num() and release() is a no-op (Serial returns 0; Threads returns the thread rank). So each host thread always maps to its own random_thr[tid]; two threads cannot get the same tid and the immediate release protects nothing that needed protecting. Kokkos is initialized with args.set_num_threads(kokkos->nthreads) (kokkos.cpp:154, re-init forces nthreads = kokkos_initialized_nthreads at 171), and RandPoolWrap::init reads kokkos->nthreads at init time, so tid < nthreads; no OOB. (Only nested OpenMP parallelism could alias IDs, which SPARTA does not use.) The pattern is the upstream LAMMPS rand_pool_wrap design.
fix: none.
