### F-G02-1
VERDICT: CONFIRMED (severity low)
reason: All five kernels (1004, 1435, 2161, 2711, 3383) only set `d_error_flag() = 1` on volume==0 and fall through to attempt_collision_kokkos (3720/3752), which divides by volume -> inf (or NaN if vremax==0). `static_cast<int>(inf)` is UB; on CUDA it saturates to INT_MAX so the per-cell attempt loop (e.g. 1031 `for m<nattempt`) runs ~2^31 iterations before the host ever reaches `if (h_error_flag()) error->one(...)` (964/1396/2121/2683/3355). CPU collide.cpp:1159 errors out immediately. The host check is only reached after the kernel completes and the retry loop exits (h_error_flag is reset at 2030/2569 each retry pass, but the final pass re-sets it), so the error is correct but arbitrarily delayed/hung. Reachability is rare (exact zero volume/weight in a cut/split cell with np>=2), hence low. Pattern present since the original upstream Kokkos file (not a regression).
fix: at each of collide_vss_kokkos.cpp:1004, 1435, 2161, 2711, 3383 replace `if (volume == 0.0) d_error_flag() = 1;` with `if (volume == 0.0) { d_error_flag() = 1; return; }`. Safe: at all five sites the check precedes `rand_pool.get_state()` so no RNG state leaks, and in the ambipolar kernels flag value 1 is still distinct from 2. Host-side check is unchanged.

### F-G02-2
