# R2-2: remap collective mode (FU-16 / FU-17 / F-G20-4 rest)
Dir: $S/r2/R2-2. A = HEAD 39e1c1f7 objects (bmpi_fixed / build), B = private objects with fix.

## Root cause
(a) remap3d_kokkos.cpp collective create builds ONE global commringlist (Allreduce of send/recv counts).
A rank with no in/out data in the plan (nsend==nrecv==0) is not in that list, but commringlen>0 for it:
- send_size/sendcnts/sdispls/recv_*/rcvcnts/rdispls are only malloc'd inside `if (nsend||nrecv)`, yet the
  store-send/recv loops over commringlen write them (:689 send_size[i] -> SEGV);
- selfcommringloc only initialised inside that block, then `plan->sendcnts[plan->selfcommringloc]` (:763);
- even past that, MPI_Comm_create gives MPI_COMM_NULL to the idle rank while commringlen>0, so
  remap_3d_kokkos would Alltoallv on MPI_COMM_NULL and destroy would MPI_Comm_free(MPI_COMM_NULL).
CPU remap3d builds a per-rank ring from its own sends/recvs (closure), so an idle rank has commringlen=0
and uses MPI_GROUP_EMPTY / MPI_COMM_NULL with no arrays.
(b) MPI_Comm_group + MPI_Group_incl groups never MPI_Group_free'd (kk :789-793, CPU :609-613).
remap2d (CPU and kk): no collective implementation (always point-to-point + MPI_Comm_dup), so neither (a)
nor (b) exists there. Sibling found in remap2d_kokkos: plan is `new` without value-init, commringlen never
set, and destroy skips MPI_Comm_free when usecollective && commringlen==0 although the comm is ALWAYS
MPI_Comm_dup'd -> uninitialised read + leaked communicator per 2d plan in collective mode.
