# R2-2: remap collective mode (FU-16 / FU-17 / F-G20-4 rest)
Dir: $S/r2/R2-2. A = HEAD 39e1c1f7 objects (bmpi_fixed / build), B = private objects with fix.

## Root cause
(a) remap3d_kokkos.cpp collective create builds ONE global commringlist (Allreduce of send/recv counts).
A rank with no in/out data in the plan (nsend==nrecv==0) is not in that list, but commringlen>0 for it:
- send_size/sendcnts/sdispls/recv_*/rcvcnts/rdispls are only malloc'd inside `if (nsend||nrecv)`, yet the
  store-send/recv loops over commringlen write them (:689 send_size[i] -> SEGV);
- selfcommringloc only initialised inside that block, then `plan->sendcnts[plan->selfcommringloc]` (:763);
- even past that, MPI_Comm_create gives MPI_COMM_NULL to the idle rank while commringlen>0, so
  remap_3d_kokkos would Alltoallv on MPI_COMM_NULL and destroy would MPI_Comm_free(MPI_COMM_NULL).
CPU remap3d builds a per-rank ring from its own sends/recvs (closure), so an idle rank has commringlen=0
and uses MPI_GROUP_EMPTY / MPI_COMM_NULL with no arrays.
(b) MPI_Comm_group + MPI_Group_incl groups never MPI_Group_free'd (kk :789-793, CPU :609-613).
remap2d (CPU and kk): no collective implementation (always point-to-point + MPI_Comm_dup), so neither (a)
nor (b) exists there. Sibling found in remap2d_kokkos: plan is `new` without value-init, commringlen never
set, and destroy skips MPI_Comm_free when usecollective && commringlen==0 although the comm is ALWAYS
MPI_Comm_dup'd -> uninitialised read + leaked communicator per 2d plan in collective mode.
Found while fixing (only reachable once the idle rank no longer crashes): remap_3d_kokkos() did
MPI_Comm_rank(plan->comm,&me) (errors on MPI_COMM_NULL for the idle rank) and compared commringlist[i]
(ranks of the ORIGINAL comm) with that SUB-comm rank to skip the self entry -> when the ring is a strict
subset (idle rank below me) the self packplan is not skipped and every later pack/unpack uses the wrong plan.

## Change summary
- src/KOKKOS/remap3d_kokkos.cpp create (collective): selfcommringloc/selfnsendloc/selfnrecvloc=-1 and self=0
  set unconditionally; store-send/recv loops, d_sendbuf allocation and self detection moved inside the
  existing `if (nsend || nrecv)` allocation block; self detection guarded by selfcommringloc>=0; after
  MPI_Comm_create a rank not in the ring (got MPI_COMM_NULL) drops commringlist and sets commringlen=0
  (= CPU behaviour: skips Alltoallv, no MPI_Comm_free). MPI_Group_free(new_group/orig_group) after
  MPI_Comm_create. remap_3d_kokkos(): removed MPI_Comm_rank(plan->comm) and use
  `isend/irecv == plan->selfcommringloc` to skip the self entry.
- src/FFT/remap3d.cpp: MPI_Group_free(new_group/orig_group) after MPI_Comm_create.
- MPI_Group_free guarded by `#if !defined(MPI_STUBS)` in both: the STUBS lib (opt/serial build) has
  MPI_Comm_group/MPI_Group_incl but no MPI_Group_free (and its groups are plain ints). (Alternative for
  the orchestrator: add an MPI_Group_free stub to src/STUBS, not owned by R2-2.)
- src/KOKKOS/remap2d_kokkos.cpp: plan value-initialised (`new ...()`); destroy always MPI_Comm_free's
  (2d always MPI_Comm_dup's; old condition read the never-set commringlen).
- src/FFT/remap2d.cpp, remap2d_kokkos.h, remap3d_kokkos.h: unchanged (no collective code / nothing to fix).
Build: $S/r2/R2-2/build.sh {mpi,opt} (private libpkg_fft.a/libpkg_kokkos.a with the 4 recompiled objects,
relinked spa_R2-2_B_{mpi,opt}); harness $S/r2/R2-2/build_harness.sh -> fftmpi_{A,B} (A = bmpi_fixed libs = HEAD),
driver = AB8 fftdrv_mpi.cpp + FNV hashes of the kk and CPU outputs (hkk/hcpu, FWD,BWD) for bitwise compares.
