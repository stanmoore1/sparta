# R2-1 (=FU-21): react/isurf/grid (+ isurf/grid) per-cell tally misplaced on fix balance steps

## Root cause
- Both computes tally during move() keyed by surf ID (== cell ID of the owning cell for implicit surfs)
  and collate in post_process_isurf_grid() via Grid::collate_array_implicit() (grid_collate.cpp:137).
- If fix balance migrates cells between the tally (move) and the post-process (dump/stats/fix after
  fix balance), a tallied cell may be neither owned nor ghost on the tallying rank anymore.
  collate_array_implicit() does `icell = (*hash)[ids[i]]`: std::unordered_map operator[] default-inserts
  the unknown ID with value 0 -> icell = 0 < nlocal -> the tally is summed into LOCAL CELL 0 of that rank
  (explains the FU-13 misplaced cells, e.g. cell (0.5,0.5), far from any surf), global sums unchanged.
  Side effect: the bogus ID->0 entry is left in grid->hash until the next rehash.
- Second facet: if a consumer post-processes BEFORE fix balance in the same step (e.g. fix ablate defined
  before fix balance, both firing), combined = 1 and array_grid is in pre-migration local order; a dump/
  stats after fix balance then reads it with post-migration indices (no reallocate()/combined reset in
  react/isurf/grid; isurf/grid reallocate() also did not reset combined). Same for adapt_grid/fix adapt.
- Kokkos variants (react/isurf/grid/kk, isurf/grid/kk) compress on host and call the CPU base
  post_process_isurf_grid(), so they inherit both.

## Change summary
- compute_isurf_grid.{h,cpp}: new public static ComputeISurfGrid::collate_tallies(sparta,nrow,ncol,ids,in,out)
  used by both computes' post_process_isurf_grid() instead of grid->collate_array_implicit():
  checks (Allreduce MAX) whether any tally ID is neither owned nor ghost on its rank; if none -> plain
  Grid::collate_array_implicit() (identical to before); else known tallies go through the normal collate,
  unknown ones are routed by one Comm::rendezvous (directory of owned cell IDs + tallies hashed by ID to
  a rendezvous proc, callback forwards each tally to the cell's current owner; tallies for cells that no
  longer exist anywhere are dropped instead of being summed into cell 0). Never default-inserts into grid->hash.
- ComputeISurfGrid::reallocate() and new ComputeReactISurfGrid::reallocate(): set combined = 0 so a grid
  change (fix balance / adapt / ablate notify) after an early post-process forces a re-collate in the new order.
- Kokkos styles: no source change needed (they compress on host and call the base post_process; the
  react/kk vtable picks up the new reallocate() override, so KOKKOS/compute_react_isurf_grid_kokkos.cpp
  and compute_isurf_grid_kokkos.cpp must be recompiled; done in the private binaries).
- Shared code NOT changed. Proposal (not mine): Grid::collate_array_implicit() should use hash->find()
  and route unknown IDs (same rendezvous) -- fix ave/grid (fix_ave_grid.cpp:734) accumulates
  tally2surf IDs over Nfreq steps and collates with it, so a balance inside its window has the same
  misplacement (see sibling test below).
