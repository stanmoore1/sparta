# R2-1 (=FU-21): react/isurf/grid (+ isurf/grid) per-cell tally misplaced on fix balance steps

## Root cause
- Both computes tally during move() keyed by surf ID (== cell ID of the owning cell for implicit surfs)
  and collate in post_process_isurf_grid() via Grid::collate_array_implicit() (grid_collate.cpp:137).
- If fix balance migrates cells between the tally (move) and the post-process (dump/stats/fix after
  fix balance), a tallied cell may be neither owned nor ghost on the tallying rank anymore.
  collate_array_implicit() does `icell = (*hash)[ids[i]]`: std::unordered_map operator[] default-inserts
  the unknown ID with value 0 -> icell = 0 < nlocal -> the tally is summed into LOCAL CELL 0 of that rank
  (explains the FU-13 misplaced cells, e.g. cell (0.5,0.5), far from any surf), global sums unchanged.
  Side effect: the bogus ID->0 entry is left in grid->hash until the next rehash.
- Second facet: if a consumer post-processes BEFORE fix balance in the same step (e.g. fix ablate defined
  before fix balance, both firing), combined = 1 and array_grid is in pre-migration local order; a dump/
  stats after fix balance then reads it with post-migration indices (no reallocate()/combined reset in
  react/isurf/grid; isurf/grid reallocate() also did not reset combined). Same for adapt_grid/fix adapt.
- Kokkos variants (react/isurf/grid/kk, isurf/grid/kk) compress on host and call the CPU base
  post_process_isurf_grid(), so they inherit both.
